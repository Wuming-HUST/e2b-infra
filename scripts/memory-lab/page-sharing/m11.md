# M11：并发块设备与网络 checkpoint

`m11_setup.sh GO_BINARY MATCHED_KERNEL_MODULE_ROOT NEW_FIXTURE_DIRECTORY`
构建 ARM64 guest 并复制匹配内核的五个 virtio/network 模块。输入目录保持只读。

```sh
sudo -n python3 scripts/memory-lab/page-sharing/m11_check.py \
  --firecracker /absolute/patched-firecracker --kernel /absolute/vmlinuz \
  --guest-binary /absolute/new-fixture/m11-guest \
  --nbd-helper /absolute/page-sharing-source \
  --module-dir /absolute/new-fixture/modules \
  --output /absolute/new-run --cleanup-failed
```

需要 root、KVM、NBD、TAP 和 4 KiB host/guest 页。测试使用 2 vCPU、128 MiB
guest、四个 O_DIRECT worker、真实 Async/io_uring 块 I/O 和持续 TAP RX。
B0/File 和 B1/NBD 各执行三轮冻结、完整 RAM/native/disk oracle，再恢复验证
所有 worker 和网络继续推进。仅操作本次创建的 VM、helper、TAP 和文件。

测试盘为 raw virtio-blk，不能替代应用 rootfs 或完整原 trace。诊断变量
`M11_DIAGNOSTIC_SKIP_NATIVE=1` 的结果不计入验收。故障现场默认保留；
`--cleanup-failed` 仅授权清理本轮 children。

设备状态顺序修复、错误传播、vsock 兼容边界、五项 Rust 合同、严格旧版本失败
及最终同源构建证据见[本轮 M11 报告](../../../deliveries/page-sharing/20261030-step1-followup/m11/m11.md)。
