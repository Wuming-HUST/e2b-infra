# M10：真实 balloon/FPR discard 与恢复

`m10_guest.go` / `m10_check.py` 是独立测试 fixture。它不改 host swap、全局 cache、原 guest 镜像或 guest rootfs，也不操作 runner 之外的 VM/NBD。需要 Linux KVM、NBD、root、4 KiB host/guest pages，以及与 guest kernel **精确匹配**的 `virtio_mmio.ko` 和 `virtio_balloon.ko`。

```sh
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o guest-init-m10 m10_guest.go
sudo python3 m10_check.py \
  --firecracker /absolute/firecracker --kernel /absolute/vmlinuz \
  --guest-binary /absolute/guest-init-m10 --nbd-helper /absolute/page-sharing-source \
  --module-dir /absolute/matching/kernel/drivers/virtio \
  --output /absolute/new-m10-balloon --cleanup-failed

# 相同参数、独立 output；balloon target/actual 保持零，仅运行 guest FPR。
sudo python3 m10_check.py \
  --firecracker /absolute/firecracker --kernel /absolute/vmlinuz \
  --guest-binary /absolute/guest-init-m10 --nbd-helper /absolute/page-sharing-source \
  --module-dir /absolute/matching/kernel/drivers/virtio \
  --output /absolute/new-m10-fpr --free-page-reporting --cleanup-failed
```

测试使用 192 MiB VM。guest 先分配 40 MiB arena 并填 `0x6b`，通过 guest pagemap 记录其 GPA。两个 VM 从同一只读 NBD source 恢复：

- balloon 模式在源快照前释放 arena，目标 VM inflate 96 MiB；必须观察 `actual_mib=96`。
- FPR 模式在源快照中保留 arena，只有目标 VM 恢复后释放；必须观察 balloon target/actual 均为 0，同时 FC `free_page_report_count/freed` 增长且 `fails=0`。
- 只选择父源真实为 `0x6b`、目标 VM 实际被匿名 remap 且最终全零的页。FPR 期间 kernel 可以重新使用少数页；这些非零页不纳入未写 oracle。至少存在一个候选，否则失败。
- 未写状态导出全部 192 MiB RAM，并与同一冻结状态的 FC native dump 比较完整 hash；再次 native dump 必须相同。
- 目标 guest 在 deflate 后重新分配 100 MiB 并填 `0xa5`；必须实际复用至少一个前述 discard GPA。再次保存，核对这些页最终为 `0xa5`。
- 两个 checkpoint 均再次恢复：未写页保持零，重写页保持 `0xa5`；guest 还会验证整个重写 arena hash。另一 VM 对应页必须保留 `0x6b`，不可变 source 完整 SHA256 不变。

每个子进程有独立 `pid.json`，API/serial/设备 metrics 原始回执保留。`cleanup.json` 记录全部本次 VM/helper 的退出状态；失败默认保留现场，显式 `--cleanup-failed` 才逐个尝试结束本次 children。close 错误逐项记录；只有所有 VM 的退出均由本次 Popen 确认后才能 drain helper。存在未知映射时写入 `quarantine.json`，runner 留存并持续读取 helper stdout，避免断管 SIGPIPE 提前结束 RAM source；此状态不自动重试 VM、disconnect 或复用设备，需按 PID 回执人工调查。SIGINT/SIGTERM 只写回执而不丢弃未知映射 source。不要删除或重启状态不明的远端进程。

该 fixture 证明真实 guest 驱动、FC File/NBD MAP_PRIVATE、discard、隔离和 native checkpoint 机制；`kvm_check.export_memory` 是独立 oracle，不代替编排器 `Sandbox.Pause` 集成测试或原应用 trace 验收。guest 实际版本由 `guest-probe.json` 记录，不能把 host 6.6 当作 guest 6.6。`/proc/config.gz` 缺失时保留缺失证据，模块实际加载、驱动绑定和成功 reporting 才是能力依据。

失败清理合同可运行 `python3 m10_cleanup_test.py -v`；其 Fake VM/helper 不执行真实 signal、KVM 或 NBD 操作。
